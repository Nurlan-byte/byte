# Локальный эксперимент Poisson

Отдельный инструмент исторической оценки, не модель в API и не источник подтверждаемого плана. Реальная история пекарни не предоставлена. Метрики на синтетике проверяют только исполнение кода и не доказывают точность или экономию.

CSV использует тот же контракт, что приложение: `date,product_id,is_open,opening,produced,sold,waste,closing,other_out,stockout_status`; `is_open` принимает 0/1/true/false. ID остаются строками. Импорт целиком отклоняется при ошибке; неизвестные ID здесь допускаются для независимых экспериментов (каталог проверяет API).

В среде с Python и установленными зависимостями:

```powershell
python -m pip install -r tools/requirements.lock
python -m unittest discover -s tools/tests -v
python tools/evaluate.py fixtures/synthetic_demo.csv --source synthetic --split-date 2026-09-28 --output private/local-report.json
```

Укажите фактический путь CSV и дату разделения. Все продукты разделены одной календарной датой: обучение строго раньше, проверка позже. Нужно минимум 28 обучающих дат, 7 дат проверки и 14 обучающих строк для каждого продукта проверки. Иначе отчёт `refused`, без вымышленных метрик.

Допущение: исторические дневные сведения доступны до начала следующего дня. В оценке только открытые дни с `stockout_status=none` и нулевым начальным остатком. Продажи — несовершенный заменитель спроса. Недостающие дни не становятся нулями. Лаги 7/14 дней календарные; imputer, scaler и encoder обучаются только на обучении. Проверка последовательная: для более позднего дня можно использовать уже наблюдавшиеся предыдущие дни проверки, модель не переобучается. B0 использует ровно минус 7 дней; B1 — до четырёх подходящих таких же дней недели за 56 дней. B0 без подходящей даты возвращает отсутствие прогноза. Наборы строк для метрик методов могут различаться; число доступных/недоступных строк приведено явно.

JSON содержит SHA256 исходного CSV, версию конфигурации, источник и разделение. Отчёты и реальные данные оставляйте локально. Модель не сохраняется, загрузка pickle/joblib не поддерживается. Подбор гиперпараметров, полноценные метрики по продуктам и реальное позднее тестирование остаются будущей работой.

Общие CSV и B0/B1 находятся в backend/imports.py и backend/forecasting.py. Политика эксперимента явно исключает opening>0, разрешает closing>0 для численной диагностики; API отдельно отключает автоматический выпуск при переносе остатков. Закрытый день с produced/sold>0 отклоняется общим парсером. Offline допускает другие строковые ID, API — только каталог.
