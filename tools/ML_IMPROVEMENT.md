# Ограниченный эксперимент улучшения ML

Протокол фиксируется до новых запусков: [ml_improvement_protocol.json](ml_improvement_protocol.json). Четыре конфигурации двух семейств — Ridge и небольшой HistGradientBoosting — учатся поправке к B1. Это именованные ML residual-модели, а не переименование неизменённого B1. B0, B1 и прежний Poisson остаются отдельными неизменёнными вариантами.

Train/validation/test и5 позиций сохраняются. Test уже просмотрен в предыдущем этапе: новый итог будет exploratory, а не независимым final test. Когорта выбирается на cutoff2017-01-31; все четыре rolling CV folds находятся после него в феврале. Внутренние folds могут учиться на более раннем validation-префиксе, но никогда на своём будущем; итоговая validation/test модель учится только на original train. Признаки/преобразования каждого fold используют только его прошлую историю. MAE и WAPE на одинаковых labels дают одинаковый порядок; WAPE не считается отдельным подтверждением выигрыша. Рейтинг моделей не использует test.

Бюджет —4 конфигурации,2 семейства, максимум36 fits, без дополнительного поиска после просмотра результатов. Выбор по validation MAE с заранее заданными проверками CV, покрытия, per-item деградации и чувствительности к неизвестным SKU. При отсутствии материального устойчивого выигрыша остаётся B1. Автоматического внедрения в производственный план нет: цель — товарные строки, не изделия/спрос/экономия.

## Запуск

Из корня репозитория после установки `backend/requirements.txt` и `tools/requirements.txt`:

```powershell
.\.venv\Scripts\python.exe tools/compare_sales_ml.py --csv <private-sales.csv> --output <private-report.json> --source external-sales-only --history-mode rolling-one-day-ahead --expected-sha256 5f7e0af51f4bf985f0d2ac2e35209c94d2426726993b98d1c2e9d8bc145860ee
```

Внешний файл должен совпадать с замороженным SHA256. Исходный CSV и полный отчёт с построчными прогнозами храните вне публичного репозитория. `--source synthetic-sales-only` предназначен только для технических проверок; даты и состав пяти позиций остаются фиксированными. Отчёт содержит все 4 конфигурации, 30 попыток обучения, причины допуска/отказа, покрытие и B1 fallback. Test оценивает только выбранный вариант, без повторного отбора. Код не изменяет SQLite или рабочий API планирования.

Проверки: `python -m unittest discover -s tools/tests -v` и `python -m ruff check backend tools`.
