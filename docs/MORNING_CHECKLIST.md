# Утром: короткая проверка локального BakePlan

Нужны ноутбук и установленные зависимости. Если Docker ещё не настроен, сначала используйте нативный запасной путь. Здесь нет платных действий и публикации в интернет.

## Первые три действия

1. Открыть отдельный checkout, сверить SHA с зелёным CI в [VERIFICATION](../VERIFICATION.md) и запустить уже готовый вариант Windows/native либо Docker по инструкции ниже. Рабочие данные сохранить.
2. На отдельной demo SQLite повторить [точный сценарий](DEMO.md): синтетика, дата `2026-10-13`, cutoff `2026-10-11`, выпуск пшеничного хлеба 84, подтверждение/история/CSV и restart с тем же файлом. Записать результат ручной проверки, затем репетировать 90 секунд и резервную запись.
3. Сверить SHA выбранной для показа версии с её проверками и материалами. Статус отдельной установленной UI-версии — в [remaining tasks](REMAINING_TASKS.md); этот checklist не является командой передеплоя.

## Подробные шаги

1. **Откройте отдельную копию проверенной ветки.** Не удаляйте старую рабочую папку и SQLite. Выполните `git rev-parse HEAD` и сравните с финальным зелёным SHA в [проверках основной ветки](../VERIFICATION.md). Для другой установленной версии нужны её собственные SHA и доказательства.
2. **Выберите готовый способ запуска.** Если уже настроены Docker Desktop + Ubuntu/WSL2, следуйте [Windows Docker-инструкции](LOCAL_WINDOWS.md): отдельный `bakeplan-local` project, `compose up -d --wait --wait-timeout 90`, затем http://127.0.0.1:8080. Пароль вводит владелец локально; присылать его в чат не нужно. Если Docker ещё не готов, используйте нативный запасной путь [руководства разработчика](DEVELOPMENT.md#быстрый-запуск): Python 3.14, Node 24, два терминала API + frontend, затем http://127.0.0.1:5173.
3. **Импортируйте синтетику.** «Данные» → «Загрузить демо CSV» → источник `synthetic` → «Проверить и импортировать». Это вымышленные данные. Укажите дату `2026-10-13`, срез `2026-10-11`: исторический replay с тем же горизонтом t−2.
4. **Пройдите основной путь.** «Модель» → обучить модель → дождаться статуса → получить прогноз → проверить фактический метод по каждому товару → «План» → выбрать ML → рассчитать → пшеничный хлеб 84 → подтвердить. Если модель не готова, B1 и причина должны быть явно видны; не называть такой прогноз ML.
5. **Проверьте сохранность.** Обновите страницу, «История» → «Обновить историю» → «Открыть план» у подтверждённой даты, экспортируйте CSV. Полностью перезапустите API с той же SQLite (в Docker `compose restart api`) и повторно откройте модель/план/экспорт. Для Docker сделайте backup и отдельную репетицию restore по [инструкции](LOCAL_WINDOWS.md); она создаёт новое имя БД и сохраняет исходное. Не используйте `down --volumes`, factory reset или volume prune.
6. **Запишите фактический результат.** SHA, Windows/Python/Node либо Docker/WSL версии, что прошло, текст ошибки и шаг при сбое. Проверки CI не заменяют этот запуск на ноутбуке. Полный checklist для Диаса — [manual QA](manual-qa.md), показ на 90 секунд — [DEMO](DEMO.md).

Локальная loopback-ссылка работает только на вашем компьютере. Для внешнего показа отдельно подтвердите доступ, HTTPS и ручную приёмку именно установленной версии; CI основной ветки этого не подтверждает. Реальные данные, независимая оценка и денежная экономия этим сценарием не подтверждаются.
