# Утром: короткая проверка локального BakePlan

Нужны ноутбук и установленные зависимости. Если Docker ещё не настроен, сначала используйте нативный запасной путь. Здесь нет платных действий и публикации в интернет.

## Первые три действия

1. Открыть отдельный checkout, сверить SHA с зелёным CI в [CI ветки материалов защиты](https://github.com/Nurlan-byte/byte/actions?query=branch%3Afeature%2Fbakeplan-defense-evidence) и запустить уже готовый вариант Windows/native либо Docker по инструкции ниже. Рабочие данные сохранить.
2. На отдельной demo SQLite повторить [точный сценарий](DEMO.md): синтетика, дата `2026-10-13`, cutoff `2026-10-11`, выпуск пшеничного хлеба 84, подтверждение/история/CSV и restart с тем же файлом. Записать результат ручной проверки, затем репетировать 90 секунд и резервную запись.
3. Выбрать размещение для внешней ссылки и согласовать его отдельно. До решения локальная версия и материалы остаются резервом; платные ресурсы автоматически не создаются.

## Подробные шаги

1. **Откройте отдельную копию проверенной ветки.** Не удаляйте старую рабочую папку и SQLite. Выполните `git rev-parse HEAD` и сравните с финальным зелёным SHA в [CI ветки материалов защиты](https://github.com/Nurlan-byte/byte/actions?query=branch%3Afeature%2Fbakeplan-defense-evidence). Не ориентируйтесь на старую default-ветку.
2. **Выберите готовый способ запуска.** Если уже настроены Docker Desktop + Ubuntu/WSL2, следуйте [Windows Docker-инструкции](LOCAL_WINDOWS.md): отдельный `bakeplan-local` project, `compose up -d --wait --wait-timeout 90`, затем http://127.0.0.1:8080. Пароль вводит владелец локально; присылать его в чат не нужно. Если Docker ещё не готов, используйте нативный запасной путь [README](../README.md#быстрый-запуск): Python 3.14, Node 24, два терминала API + frontend, затем http://127.0.0.1:5173.
3. **Импортируйте синтетику.** «Демо» → источник `synthetic` → «Проверить и импортировать». Это вымышленные данные. Укажите дату `2026-10-13`, срез `2026-10-11`: исторический replay с тем же горизонтом t−2.
4. **Пройдите основной путь.** Обучить модель → дождаться статуса → получить прогноз → проверить фактический метод по каждому товару → выбрать ML в плане → рассчитать → пшеничный хлеб 84 → подтвердить. Если модель не готова, B1 и причина должны быть явно видны; не называть такой прогноз ML.
5. **Проверьте сохранность.** Обновите страницу, откройте подтверждённый план из истории, экспортируйте CSV. Полностью перезапустите API с той же SQLite (в Docker `compose restart api`) и повторно откройте модель/план/экспорт. Для Docker сделайте backup и отдельную репетицию restore по [инструкции](LOCAL_WINDOWS.md); она создаёт новое имя БД и сохраняет исходное. Не используйте `down --volumes`, factory reset или volume prune.
6. **Запишите фактический результат.** SHA, Windows/Python/Node либо Docker/WSL версии, что прошло, текст ошибки и шаг при сбое. Проверки CI не заменяют этот запуск на ноутбуке. Полный checklist для Диаса — [manual QA](manual-qa.md), показ на 90 секунд — [DEMO](DEMO.md).

После этого остаётся выбрать и одобрить размещение для внешней ссылки. Локальная ссылка работает только на вашем компьютере. До отдельного выбора хоста, HTTPS и проверки извне публичное демо не считается готовым. Реальные данные, независимая оценка и денежная экономия этим сценарием не подтверждаются.
