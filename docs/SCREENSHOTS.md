# Реальные снимки интерфейса: автоматическая съёмка

Этот файл описывает воспроизводимый сбор доказательств, а не утверждает, что снимки уже получены. Снимки считаются готовыми только после успешного шага `Capture real synthetic UI evidence` и проверки `capture_status: complete` в `manifest.json` того же CI-run.

## Что именно запускается

- Отдельный Playwright Chromium открывает настоящее приложение: Vite на `127.0.0.1:15174`, FastAPI на `127.0.0.1:18002`.
- Каждый запуск получает новую пустую временную SQLite. Она не совпадает с БД основного E2E-набора и не публикуется.
- Через интерфейс импортируется только сохранённый в Git `fixtures/synthetic_demo.csv`, с явными `source=synthetic`, `sold_units / physical_unit` и описанием происхождения. Никаких приватных историй, учётных данных или производственной БД.
- Дата — `2026-10-13`, включительный срез — `2026-10-11`, историческое воспроизведение и горизонт t−2. До обучения проверяется явный B1 fallback; затем обучается реальная модель и проверяется ML-прогноз. ML-план демонстрирует p1: прогноз около 27,64 в текущем v3 (около 29,76 в pinned v2 baseline), рекомендация 24, ручной выпуск 84. Недопустимые 90 сначала блокируются. После подтверждения страница перезагружается, план открывается из истории и сверяется с API/CSV.
- Ответы API не подменяются, DOM и CSS не изменяются для съёмки. Допускаются только обычные действия: ввод, выбор, раскрытие деталей, прокрутка и смена размера viewport. Скриншоты не составляются из частей и не ретушируются. Анимации и каретка отключены стандартными опциями Playwright.

## До и после UI-polish

Windows CI запускает один capture-harness дважды: сначала нетронутый worktree commit `756829475615d37d024b12e720d7cfc9338e4b68` (baseline), затем текущий SHA. Отдельные временные SQLite и frontend-процессы исключают смешение состояний. `before/` содержит 13 PNG, `after/` — 14 PNG; всего 27. В обоих manifest отдельно записаны `source_sha`, `harness_sha`, `source_dirty`, `capture_variant`. Harness не изменяет baseline UI/DOM/CSS.

Файлы 11–13 показывают один и тот же подтверждённый план, с началом раздела `#planning` у верхнего края viewport, закрытыми источниками и таблицей в начальной горизонтальной позиции. Ширины строго 360, 768 и 1440. Дополнительный after-only файл 14 показывает весь рабочий экран с заголовком, навигацией и импортированными данными перед подтверждением. Это разные явно подписанные поверхности; их нельзя подменять друг другом.

## Получение и проверка

В успешном GitHub Actions run `BakePlan checks` откройте артефакт `bakeplan-ui-evidence-<source SHA>-<run attempt>`. Срок хранения — 14 дней. Для скачивания приватного репозитория необходим соответствующий доступ; ссылка на run без прав не гарантирует доступ к файлам. Вложенные папки `screenshots/before/.../evidence` и `screenshots/after/.../evidence` содержат PNG/CSV/manifest и копию этой инструкции. Дополнительная папка `defense-replay` содержит отдельный API replay, запускаемый после снимков; его БД также временная и не публикуется. Идентификаторы наборов и моделей разных запусков могут различаться. При ошибке могут сохраниться частичные снимки и Playwright trace: `capture_status: incomplete` не является готовым комплектом.

Перед передачей снимков:

1. Проверьте, что SHA в after-manifest соответствует нужному исходному коммиту, а before-manifest — pinned baseline; harness SHA соответствует CI-кандидату; `source_dirty=false`, `capture_status=complete`, а шаг съёмки прошёл. `fixture.raw_sha256` описывает прочитанные байты; `fixture.canonical_lf_sha256` нормализует только CRLF→LF для сопоставления с Git/replay при Windows checkout. PNG/CSV имеют собственные hashes исходных байтов, без нормализации.
2. Откройте PNG и проверьте читаемость, кадрирование и нужные состояния. Автоматические проверки не заменяют визуальный просмотр готовых снимков.
3. Убедитесь, что количество 84 относится к подтверждённой редакции, а ≈27,64/24 у текущего v3 (≈29,76/24 у baseline v2) — к прогнозу ML и рекомендации. Сверяйте версию модели и точные числа manifest. Сверьте CSV.
4. Сохраните скачанный комплект до истечения 14 дней, если он нужен для защиты позже. Не называйте его ручной или production-проверкой.

Локальное воспроизведение после установки зависимостей по README:

```sh
npx playwright test --config=playwright.screenshots.config.ts
```

На Windows используйте `npx.cmd`. Вывод появится под `test-results/screenshots/` и исключён из Git. Исходные 18 E2E-сценариев сохранены с навигационными селекторами нового интерфейса; ещё 5 проверяют клавиатуру, сохранение черновиков/прогноза и ширины 360/768/1440 (всего 23). Capture запускается отдельно от них. В cloud-окружении с запретом браузерных сокетов реальная съёмка недоступна; запуск и получение PNG должны быть проверены в CI, без подмены нарисованными макетами.
