# Оценка интегрированной модели без подмены горизонта

## Что именно проверяем

Рабочая гипотеза: план составляется в день d для d+1, полные факты доступны только до d−1. Поэтому целевая дата t использует срез t−2. Это консервативное допущение, пока владелец пекарни не подтвердил время готовности учёта. Если факты запаздывают, срез нужно сдвинуть ещё назад; такие прогнозы не покрываются двухдневной оценкой.

Встроенная оценка нового протокола Ridge использует тот же горизонт. Это временной holdout внутри загруженного набора, а не независимый эксперимент. B1 и ML сравниваются только на одних и тех же пригодных парах товар/дата, с общей доступной историей. Отдельно указаны парное N, MAE, покрытие, исключения и показатели по товарам. Пропущенные дни не заполняются продажами 0. `ready` означает техническую готовность, не победу над B1.

## Воспроизведение процедуры на синтетике

После чистой установки из README, из корня:

```sh
.venv/bin/python tools/evaluate_forward.py fixtures/synthetic_demo.csv \
  --source synthetic \
  --provenance "Generated BakePlan fixture; no real bakery data" \
  --training-cutoff 2026-09-27 --start 2026-09-29 --end 2026-10-11 \
  --output private/synthetic-forward-smoke.json
```

PowerShell: замените `.venv/bin/python` на `.\.venv\Scripts\python.exe` и выполните команду в одну строку. Для `sales-1` добавьте `--target item_line_count`; единица останется `item_line`. Она не преобразуется в физические штуки.

Это использует именно интегрированный `train_model/forecast_model`, а не старый Poisson/offline pipeline. Параметры обучаются только до `training-cutoff`, затем заморожены. Первый оцениваемый день должен быть не раньше training-cutoff+2. Для каждой поздней даты обновляется только доступная наблюдаемая история до t−2; модель не переобучается по holdout, гиперпараметры не выбираются по результатам. Отчёт содержит SHA-256 данных, протокол, обучающий snapshot, даты, число пригодных наблюдений, фактические методы и общие пары. Fallback не считается ML-прогнозом и уменьшает парное покрытие. Не сравнивайте MAE на разных множествах строк.

Синтетический результат служит проверкой процедуры. Его численные ошибки не являются заявлением о точности, экономии или пользе для реальной пекарни.

## Независимый будущий запуск: задача команды

1. Асыл получает разрешённую историю одной пекарни, описание единиц и времени готовности каждого дневного итога. Только `sold_units / physical_unit` с проверяемым балансом пригоден для производственного сценария. Историю хранить вне Git и публичного демо.
2. Нурлан до просмотра будущих результатов фиксирует commit, протокол, training-cutoff, период наблюдения, ассортимент, горизонт, правила исключения, парное сравнение и критерий полезности вместе с владельцем. Сохранить исходный файл и его хеш. Предварительно согласовать критерий, не выбирать его по получившимся ошибкам.
3. В наблюдательном режиме ежедневно сохранять выпущенный прогноз B1/ML, его cutoff, фактический метод, доступную тогда историю и выбранный владельцем выпуск. Если учёт появился поздно или был исправлен задним числом, не подменять исходный snapshot более свежими сведениями; отметить дату как нарушение допущения и отдельно разобрать.
4. После окончания зафиксированного периода выполнить CLI на разрешённом файле с теми же датами, затем сверить восстановленные прогнозы с ежедневными сохранёнными снимками. Одного позднего CSV недостаточно для доказательства того, что сведения были доступны вовремя. Отчёт намеренно всегда пишет `independence: unverified`; независимость подтверждается журналом и процедурой, не флагом CLI.
5. Диас повторяет расчёт из чистого checkout, проверяет общие пары/покрытие/исключения, restart/export и отсутствие будущих фактов. Асыл с владельцем оценивают практическую применимость. Если ML хуже B1 или покрытие низкое, это публикуется как результат; B1 остаётся доступен.

Сейчас разрешённая реальная история, журнал доступности и независимый будущий период не предоставлены. Эта работа открыта. Уже просмотренный BreadBasket test и старое улучшение 3,35% относятся к историческому sales-only эксперименту; они не являются результатом нового протокола. Скрытый спрос, причинный эффект и денежная экономия здесь не измеряются.
