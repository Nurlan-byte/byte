# Открытая работа и критерии завершения

Состояние репозитория проверяется по точному SHA в [VERIFICATION](../VERIFICATION.md). Зелёный CI подтверждает автоматические проверки; ручная приёмка конкретной установленной версии и качество на реальной истории фиксируются отдельно.

| Ответственные | Результат | Готово, когда |
|---|---|---|
| Нурлан + Диас | Приёмка конкретной deployment-версии | Записаны SHA, окружение и фактический результат; с другого устройства проверены доступ, импорт → метод → план → сохранение/export, restart и restore в новый файл без потери данных |
| Диас + Бага | Независимая laptop/phone QA | Пройден [manual QA](manual-qa.md), зафиксированы размеры/браузер, ошибки сети, устаревшие поля и реальные результаты; viewport Chromium не выдан за физический телефон |
| Асыл + владелец пекарни | Разрешённая история и доступность фактов | Согласованы target/unit, баланс, ассортимент, календарь и задержка учёта; есть разрешение на использование и журнал доступности |
| Нурлан + Диас | Независимая будущая оценка B1/ML | Зафиксирован протокол до просмотра нового периода; отчёт содержит общие пары, N/MAE/coverage/исключения и cutoff по [EVALUATION](EVALUATION.md) |
| Асыл + команда | Комплект защиты | Сверены регламент и срок с организатором; презентация/видео соответствуют показанному SHA, синтетика подписана, копия CI-артефактов сохранена до истечения retention |

Пользователь сообщил об отдельной установленной UI-версии `feature/bakeplan-owner-ux` на `bbf516958924cd8a673329ca7ef2dfbdfe0b2311`. Она не опубликована в GitHub и не входит в эту очистку. Решение о её публикации и согласовании с основной веткой остаётся отдельной задачей. Репозиторный CI не проверяет эту VM; существующие VM, Docker, SSH, внешний туннель и deployment backups при очистке не меняются.

Без новой предметной задачи не расширять фиксированный каталог p1…p5, партии/лимиты, ML, API или SQLite schema 3. В UI нет изменения партии/лимита; нет POS/CRM, общей модели печи, денежной оптимизации, восстановления скрытого спроса, пользовательских аккаунтов и границ доступа между пекарнями. Эти возможности не обещаются в показе. Старые внутренние сроки сохранены только в [архивном аудите](archive/MVP_AUDIT.md), а не представлены как подтверждённый регламент.
