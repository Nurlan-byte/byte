## Автоматический заказ Chronos-2

Проверили правило Chronos-2/B1 из версии `082a535` на последних семи наблюдаемых датах каждой из четырёх выборок. На вход подавали только продажи, известные за два календарных дня до целевой даты. Сопоставляли одни и те же товары с прежней версией BakePlan по истории продаж. Для Chronos-2 использовали ожидаемое количество по всем квантилям. Для редких товаров B1 мог заменить Chronos по более ранним парным ошибкам. В кафе прогнозируем число чеков, в которых встретился напиток. Физический заказ поставщику требует данных в штуках.

| Выборка | Товаро-дней | MAE прежней версии | MAE нового расчёта | Изменение ошибки | Chronos-2 / B1 |
|---|---:|---:|---:|---:|---:|
| Пекарня | 42 | 7,356 | 7,243 | −1,53% | 42 / 0 |
| Три кафе | 126 | 0,691 | 0,721 | +4,27% | 110 / 16 |
| Вендинг | 42 | 0,624 | 0,589 | −5,57% | 23 / 19 |
| Панель покупок | 56 | 0,456 | 0,442 | −2,89% | 20 / 36 |

**Откуда взялись +4,27% в кафе.** С 24 по 30 сентября 2025 года сумма абсолютных ошибок выросла с 87,1169 до 90,8345 на 126 одинаковых товаро-днях. Это дополнительно 0,0295 чека на товар в день относительно прежнего BakePlan. В 59 случаях напиток не встретился ни в одном чеке. На них пришлось 3,6304 из 3,7176 дополнительной суммарной ошибки (97,7%). На остальных 67 наблюдениях разница составила 0,0872. Относительно простого B1 на тех же датах ошибка Chronos-2/B1 **ниже на 3,88%**. Обе величины рассчитаны из неокруглённых ошибок.

## Проверка поправок для трёх кафе

На 378 товаро-днях напитков за 6–26 августа 2025 года сравнили три способа использовать недавние продажи. Для сентябрьской проверки выбрали среднее двух величин с равным весом — действующего прогноза и средней частоты чеков за последние 28 дней. Условия выпуска задали до сравнения. В каждой группе средняя абсолютная ошибка должна снизиться минимум на 1%, охват должен сохраниться, а величина смещения общего объёма может вырасти максимум на два процентных пункта. Смещение показывает, на сколько процентов суммарный прогноз выше или ниже факта. [Правила отбора и расчёта](receipt_quality_protocol.json) · [Отчёт с разбивкой по точкам](results/receipt_quality.json)

Отдельно повторили расчёт с неизвестными датами после последней покупки товара на момент прогноза. На тех же сентябрьских исходах поправка снизила MAE на 1,96% для напитков и 1,18% для закусок. Это проверка обработки отсутствующих наблюдений. Для неё использовали те же даты, а не новые данные из касс.

В исходную неделю ошибка снизилась с 0,7209 до 0,6734, на 2,61% ниже прежнего BakePlan. Однако на закусках за весь сентябрьский проверочный период ошибка выросла на 3,17%. Товары и точки отбирали только по предшествующей истории. Для каждой целевой даты брали факты максимум по дату двумя днями ранее. В пекарне, кафе и вендинге модель обновляли еженедельно, для панели покупателей зафиксировали модель от 4 ноября 2017 года. В таблицах `metrics.csv` показатель `error_reduction_pct` положителен при снижении ошибки. WAPE — суммарная абсолютная ошибка, делённая на сумму фактических значений, в процентах. При отсутствии фактических продаж знаменатель равен нулю, поле остаётся пустым. Дни без какой-либо зарегистрированной операции в точке пропущены. На наблюдаемый день отсутствие покупки выбранной позиции означает ноль зарегистрированных покупок. Спрос покупателей, которым товар не достался, неизвестен.

## Редкие продажи в штуках: Chronos‑2, B1 и TSB

Сравнили рабочее правило Chronos‑2/B1 с моделью Teunter–Syntetos–Babai из StatsForecast 2.0.3. TSB отдельно обновляет вероятность ненулевой продажи и количество штук при продаже. В эксперименте она может повлиять на прогноз, когда за последние 56 календарных дней набралось хотя бы 28 наблюдений и более половины из них — нули. В остальные дни все кандидаты возвращают рабочий прогноз. Пропущенные даты остаются неизвестными. Каждый прогноз использует только историю, доступную за два календарных дня до целевой даты. [Протокол отбора и выпуска](sparse_tsb_protocol.json) · [Модель TSB](https://nixtlaverse.nixtla.io/statsforecast/docs/models/tsb.html)

На 21 дате каждого источника сравнивались TSB и три смеси с рабочим прогнозом. Один вариант выбрали для всех четырёх источников до проверки на следующих 28 наблюдаемых датах. У трёх магазинов M5 это 25 апреля — 22 мая 2016 года. У автомата это 25 ноября — 30 декабря 2022 года. Панель M5 впервые используется в оценке BakePlan; период автомата уже изучался. Возможное присутствие публичных рядов в предобучении Chronos отдельно не проверялось.

Для воспроизведения подготовьте [панель M5 и окружение Python 3.12](m5-panel.md) и файл `private/bench/vending/vending_daily.csv` по инструкции выше. Первую команду выполняют штатным Python BakePlan с установленной моделью. Аргумент `--tsb-python` указывает на отдельное окружение с зависимостями из `requirements-sparse.lock`. Для Windows укажите путь вида `.venv-sparse/Scripts/python.exe`.

```sh
python benchmarks/open-sales/scripts/evaluate_sparse_tsb.py --m5-panel private/m5-panel.csv --vending-daily private/bench/vending/vending_daily.csv --tsb-python .venv-sparse/bin/python --output private/sparse_tsb.json
python benchmarks/open-sales/scripts/evaluate_sparse_tsb.py --verify-report benchmarks/open-sales/results/sparse_tsb.json
```

На контрольном периоде выбранный на этапе разработки вариант сдвигал прогноз на половину расстояния к TSB только тогда, когда TSB предсказывал меньшие продажи. Положительное смещение означает завышение суммарных продаж, отрицательное — занижение. [Отчёт с суммами ошибок, смещением в штуках и результатами для редких товаров](results/sparse_tsb.json)

Покрыты все 672 запланированные пары. Среднее по четырём источникам относительное снижение MAE составило 2,05%. В магазине WI_1 кандидат занизил объём на 7,01 штуки из 153 против 2,37 у рабочего прогноза. Рост абсолютного смещения на 3,03 процентного пункта превысил заранее установленный предел в 2 пункта.
