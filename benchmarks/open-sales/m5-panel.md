# Продажи товаров M5

Для независимой проверки редких продаж взяты наблюдаемые количества проданных единиц Walmart. В выборке 18 рядов «магазин и товар» и 336 календарных дней с 22 июня 2015 года по 22 мая 2016 года. Магазины CA_1, TX_1 и WI_1 представляют Калифорнию, Техас и Висконсин. Это дополнительная проверка на розничных продажах в США. Для оценки заказов компьютерного клуба нужны продажи и доступность товаров самого клуба. [Описание организаторов M5](https://github.com/Mcompetitions/M5-methods) · [Данные соревнования](https://www.kaggle.com/competitions/m5-forecasting-accuracy/data)

## Подготовка

Скачайте архив `m5-forecasting-accuracy.zip` (48 МБ) из версии 1 записи Zenodo и сохраните как `private/m5.zip`. Команда сверяет SHA-256 архива `0349ba38a2efd30d0f5acc6394c1110e140e1a990c650d7b5ca44c5b25dd12f5`. Внутри используются таблицы `sales_train_evaluation.csv`, `calendar.csv` и `sell_prices.csv`. Для сохранения и передачи исходных строк проверьте условия исходного соревнования. В репозитории хранятся код подготовки и агрегаты. [Архив с DOI](https://doi.org/10.5281/zenodo.12636070) · [Условия M5](https://www.kaggle.com/competitions/m5-forecasting-accuracy/rules)

В активированном отдельном окружении Python 3.12 выполните из корня проекта

```sh
python -m pip install -r benchmarks/open-sales/requirements-sparse.lock
python benchmarks/open-sales/scripts/prepare_m5.py --archive private/m5.zip --output private/m5-panel.csv --metadata private/m5-panel.metadata.json
python -m pytest benchmarks/open-sales/tests/test_prepare_m5.py -q
```

Состав товаров для каждого магазина зафиксирован по 112 дням с 20 июля по 8 ноября 2015 года. DuckDB отбирает продукты FOODS с минимум 100 наблюдаемыми днями, четырьмя ненулевыми днями и хотя бы одной продажей в первые и последние 28 дней окна. По доле дней с продажей образуются три группы с границами ⅓ и ⅔. Из каждой берутся два товара в порядке MD5 кода, при совпадении хэшей — в порядке кода. В последующие месяцы состав сохраняется при любых продажах.

Календарь даёт код недели для проверки наличия цены. Для оценки допустима явно записанная продажа, если у товара в эту неделю была положительная цена и у магазина в этот день наблюдалась хотя бы одна продажа среди всех категорий. Отсутствующую запись, отсутствие недельной цены или день без наблюдаемой активности магазина считаем неизвестными. Для известного закрытия предусмотрен отдельный статус; отдельного календаря закрытий в этом архиве нет. Цена за неделю и открытый магазин не гарантируют наличия товара на полке весь день.

Из 6 048 строк в регулярной сетке 6 042 получили наблюдаемые количества, из них ровно 3 021 нулевое. Шесть строк CA_1 за 25 декабря 2015 года остались без метки. Pandera проверяет единицы, уникальность комбинации «филиал, товар, дата» и отсутствие меток у неизвестных и закрытых дней. На выходе CSV с полями `site,product,date,sold`, SHA-256 `2256e9ab27ca7f3dbff687717ed05d8888a378f29b02ecce902ed9af63f047e2`. Соседний JSON перечисляет выбранные ряды, периоды, контрольные суммы и количество наблюдений.

## Дополнительная выборка для проверки поправки по прошлым ошибкам

До расчёта зафиксированы ещё три магазина M5, CA_2, TX_2 и WI_2. Период, архив, правила отбора шести товаров на магазин и обработки пропусков совпадают с первой выборкой. Получилось 18 новых сочетаний магазина и товара, 6 030 наблюдаемых товаро-дней, включая 2 969 нулей. Для 18 товаро-дней факт остался неизвестным. В обеих выборках представлена одна публичная сеть в те же даты. Из десяти различных товаров новой выборки восемь встречались в первой. [Протокол эксперимента](sparse_bias_protocol.json)

```sh
python benchmarks/open-sales/scripts/prepare_m5.py --archive private/m5.zip --confirmation --output private/m5-confirmation.csv --metadata private/m5-confirmation.metadata.json
```

Контрольная сумма дополнительной выборки `e34ed6d1771a07824494c6919480b759473c0082f456eb58159ae6f7da71ad77`. Для повторной оценки запустите первую команду ниже из рабочего окружения BakePlan с подготовленными весами Chronos-2. Параметр `--tsb-python` указывает на Python отдельного окружения из файла `requirements-sparse.lock`. Подтвердить расчёты в опубликованном отчёте можно второй командой.

```sh
python benchmarks/open-sales/scripts/evaluate_sparse_bias.py --m5-panel private/m5-panel.csv --vending-daily private/bench/vending/vending_daily.csv --confirmation private/m5-confirmation.csv --tsb-python .venv-sparse/bin/python --output private/sparse_bias.json
python benchmarks/open-sales/scripts/evaluate_sparse_bias.py --verify-report benchmarks/open-sales/results/sparse_bias.json
```

По 28 контрольным датам каждого магазина и автомата удалось сопоставить все 1 176 прогнозов с продажами. Среднее по группам относительное снижение MAE составило 1,34% на прежних источниках и 1,13% в трёх дополнительных магазинах. В TX_2 ошибка на товаро-день снизилась с 0,510 до 0,496 шт., а недооценка суммарного объёма выросла с 1,23% до 6,82%. Увеличение на 5,59 процентного пункта превысило установленный предел 2 п.п. Поправка не прошла критерии выпуска. В этом историческом тесте продажи дня считались известными после его завершения. Задержки импорта и фактическое наличие товара в компьютерном клубе следует измерять по локальным данным. [Агрегаты семи групп и решение](results/sparse_bias.json)
